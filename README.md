# Chat 3D

ブラウザだけで完結する、**テキスト指示 / コード実行による 3D モデル(STL)生成・編集ツール**の PoC です。
バックエンドはありません。すべて HTML / CSS / Vanilla JavaScript で動きます。

🔗 **公開版:** https://t-sumita.github.io/chat-3d/

## 表示言語(日本語 / English)

右上の **`EN` / `日本語`** ボタンで表示言語を切り替えられます(v0.10.0)。

- 初回はブラウザの言語設定から自動判定します(日本語なら `ja`、それ以外は `en`)。以降は選択を localStorage に記憶します。
- **切り替えてもページは再読み込みされません。**作業中のメッシュ・undo 履歴・チャットログはそのまま残ります。
- LLM に渡すシステムプロンプト・指示テンプレート・サンプルコードも言語に追従します。
  ただし**システムプロンプトを自分で編集した場合は上書きしません**(編集内容が消えないよう、既定文のままのときだけ差し替えます)。

## 3 つの使い方

| モード | 概要 |
| --- | --- |
| **STL 編集** | STL / 3MF ファイルをプレビュー領域に **ドラッグ&ドロップ**し、チャット指示で穴あけ・結合などの CSG 加工を行う。3MF は形状のみ読み込み、色情報は無視される。 |
| **ゼロベース生成** | STL を読み込まず、チャット指示だけで Box / Cylinder / Sphere などの基本図形 + CSG からモデルを生成する。 |
| **直接編集(チャット不要)** | 「編集」タブで、拡大縮小・消しゴム・パーツ分割・図形/文字の追加をマウスと数値入力だけで行う。 |
| **マニュアルコード実行** | ChatGPT 等で作った JavaScript を「コード」タブに貼り付け、「STL反映実行」でシーンに反映する。 |

「STL ダウンロード」ボタンで、現在のメッシュをいつでもバイナリ STL として保存できます。

## チャットの 2 つのモード

「チャット」タブでは、LLM とのやりとり方法を **コピペモード** / **API モード** の 2 種類から選べます。

| モード | 概要 |
| --- | --- |
| **📋 コピペモード**(既定) | ChatGPT / Claude など、**Gemini に限らず好きな LLM** とチャット欄外で直接やりとりする方式。①「プロンプトをコピー」でシステムプロンプト+指示をクリップボードにコピー → ②外部チャットに貼り付けて送信 → ③返ってきた回答を「外部チャットの回答を貼り付け」欄に貼って「貼り付けを実行」。この手順はチャットログにガイドとして自動表示されます。API キー登録は不要です。 |
| **🔌 API モード** | 設定タブに登録した Gemini API キーを使い、指示の送信からコード実行までを自動で行う方式。 |

## 「編集」タブ — チャットを使わない直接操作

LLM に頼らず、その場で形を直せます。すべての操作はヘッダの **↶ / ↷**(Ctrl+Z / Ctrl+Y)で元に戻せます。

| 機能 | 内容 |
| --- | --- |
| **拡大・縮小** | 全体倍率 / XYZ 個別倍率 / 目標寸法(mm)の直接指定(比率保持の切替あり)。 |
| **消しゴム** | ON にしてモデルをクリックすると、その位置を指定半径の球で削る。視点のドラッグ回転とは自動で区別される。 |
| **パーツ分割** | つながっていない塊(板・部品など)を自動認識して一覧化。選んだパーツだけを拡大縮小・削除できる。 |
| **図形の追加** | 直方体 / 円柱 / 球 / 円錐を、サイズと位置(mm)を指定して**結合**または**削り取り**。 |
| **テキスト** | 立体文字を追加 / 彫り込み。**半角英数字・記号のみ**(日本語フォントは未対応)。 |

> パーツ分割は、頂点座標を量子化して溶接し Union-Find で連結成分を求めています。STL のように
> 頂点が重複した形式でも正しく分割できます。モデルを変更すると一覧は解除されるので、再度「分割」を押してください。

> undo 履歴はジオメトリの実体を保持するため、段数を 12 に制限しています。

## 座標の調べ方(v0.11.0)

LLM は読み込んだ形を**見ていません**。「この突起を削って」は通らず、位置は必ず**座標(mm)**で
伝える必要があります。そのための目安を 3D ビューに用意しています。

| 機能 | 内容 |
| --- | --- |
| **グリッド/軸の表示切替** | 3D ビュー右下のボタン。床のグリッドは **1 マス 10mm**、原点から伸びる 3 本の線が座標軸(**X = 赤 / 左右**、**Y = 緑 / 高さ**、**Z = 青 / 奥行き**)。スクリーンショットを撮るときなどに消せます。 |
| **座標ピック** | モデルを **Shift + クリック**すると、その表面の点の座標が吹き出しに出ます。「コピー」で書き写す、「指示に挿入」でチャットの入力欄へそのまま入れる、のどちらもできます。 |

読み込んだモデルは**原点が中心**になるよう自動で移動されるので、座標は「中心からの相対位置」として
読めます。

座標ピックを ON/OFF のモードにせず Shift + クリックにしているのは、**消しゴムと取り合いにならない
ようにする**ためです。モードが 2 つ並ぶと、排他にしたところで「今どちらが動くか」を覚えていられません。
Shift なら消しゴムを ON にしたままでも座標を読めます。Shift を押している間はカーソルが変わります。

## ⏱ 重い処理と実行前ガード

CSG（ブーリアン演算）は**三角形数が増えるほど急激に遅くなり、しかも結果の三角形数を増やします**。
そのため加工を重ねるほど次の処理が重くなり、「1 回目は成功したのに 2 回目で固まる」ことが起こります。

計算はメインスレッドを占有する同期処理なので、**開始したら中止できません**。
ブラウザが「ページが応答しません」と表示した場合は **「待機」** を選べば処理は続きます。
（`RESULT_CODE_HUNG` の画面まで出てしまうと、そのタブの作業内容は失われます。）

これを踏まえ、実行前に規模をチェックします。

| 対象の三角形数 | 挙動 |
| --- | --- |
| 〜20,000 | そのまま実行。 |
| 20,000〜60,000 | 実行し、オーバーレイで「中止できない・数分かかる場合がある」旨を強調表示。 |
| 60,000 超 | **実行前に確認ダイアログ**を出す。所要時間の見積り・失敗の可能性・STL 保存の推奨を表示し、「それでも実行する」を選んだときだけ進む。 |

対象は「コード」タブの実行と、「編集」タブの CSG 操作（消しゴム / 図形の結合・削り取り）です。
実行後の「実行レポート」には**三角形数の増減**と、次回の実行が重くなる旨の警告が出ます。

あわせて、システムプロンプトで LLM 側にも三角形数の抑制を依頼しています
（分割数を控えめに指定する / CSG の回数を最小にする / 移動・回転・拡大縮小に CSG を使わない）。
現在の三角形数も LLM に渡すので、重い状態なら LLM 側がさらに保守的な生成に切り替えます。

### 保存した STL はそのまま印刷できます(v0.9.1)

「STL 保存」を押すと、書き出しの直前に**自動で水密化(修復)**を行います。
**Bambu Studio で読み込んでエラーが出ないことを確認済み**です。修復を促されずにそのままスライスできます。

**形は 1 ミクロンも変わりません。**頂点は 1 つも動かさず、既存の辺の上にだけ角を足し、
体積ゼロの面だけを取り除いているためです。

| モデル | つながっていない辺 | 非多様体エッジ | 三角形 | 体積 |
| --- | --- | --- | --- | --- |
| 20mm ダイス(実測) | **1,316 → 0** | **17 → 0** | 2,240 → 2,936 (+31%) | 変化なし |
| 12 万三角形のモデル | 数千 → 14 | — | **+3%**(v0.9.0 は +34%) | 変化なし(処理 約 4 秒) |

<details>
<summary>何を直しているのか(仕組み)</summary>

原因は **T ジャンクション**です。CSG が面を切るとき、切られた面の**隣の面までは切らない**ため、
辺の途中に他の面の角が乗った状態が残ります。実際に隙間はないのですが、面どうしが角を
共有していないため、スライサーからは「つながっていない」= 面が欠けていると見えます。
**v0.9.0** から、辺の上に乗っている角でその面を分割し直して解消しています。

**v0.9.1** ではこれに加えて、**厚みゼロの「内部の壁」**(同じ 3 点に表と裏の面が背中合わせで
重なったもの)を組ごと除去します。体積に一切寄与しない一方で、スライサーからは
「1 本の辺を 3 面以上が共有している(非多様体エッジ)」と見える面です。

これは `three-csg-ts` に限らず BSP 方式の CSG に共通の性質で、代替の `three-bvh-csg` でも
同様に発生することを実測で確認しています(→ [`docs/known-issues.md`](./docs/known-issues.md) A-6)。
</details>

### 「三角形が多すぎる」と言われたら

CSG(穴あけ・結合など)を重ねると、見た目は変わらなくても**三角形の数だけが増えていきます**。
Bambu Studio などのスライサーで警告が出ることがありますが、
**そのままスライスできるなら何もしないのが一番安全です**。

- ⚠ **簡略化(Simplify)は使わないでください。**単純に間引く処理は閉じた立体(水密)としての
  整合性まで見てくれないため、モデルに穴が開いて壊れることがあります。
- どうしても減らしたい場合は、chat-3d 側で分割数を抑えて作り直すほうが確実です
  (丸みより面取り、円筒の分割は 12〜16 など)。

「STL 保存」時にもトースト通知で軽く予告します。

### それでも修復を促されたら

他のツールや、v0.9.0 より前のバージョンで保存した STL で修復が必要になったときの注意です。

- ⚠ **修復は意図して作った部分まで消すことがあります。**細い突起・薄い板・小さな穴は、
  修復する側から見ると「壊れた部分」と区別がつきません。
- **修復の前後で形を見比べる**／**修復前の STL を別名で残す**。
- 細部が消える場合は、修復に頼らず **chat-3d 側で作り直す**ほうが早いことが多いです
  (細い部分は 1.5mm 以上、小さすぎる穴はやめる)。
- **簡略化(Simplify)は修復とは別物**です。面が欠けているときに使うと悪化します。

> 現状、作業内容の自動保存はありません。**区切りごとに「STL 保存」でバックアップしてください。**

判明している制約・未対応事項は [`docs/known-issues.md`](./docs/known-issues.md) にまとめています。

## 使いはじめ

1. リポジトリを開く（ローカルなら任意の静的サーバで配信）。
   ```bash
   # 例: Python の簡易サーバ
   python -m http.server 8000
   # → http://localhost:8000/ を開く
   ```
   > `importmap` と ES Modules を使うため、`file://` 直開きではなく **HTTP 配信**が必要です。
2. **API モードを使う場合のみ**、「設定」タブで Gemini API キーを入力
   （[Google AI Studio](https://aistudio.google.com/app/apikey) で取得）。
   キーは **ブラウザの localStorage にのみ保存**され、Subutomo のサーバには送信されません。
   コピペモードならキー登録は不要です。
3. チャットに日本語で指示するか、STL / 3MF を D&D して編集を始めます。

### 指示の例（ゼロベース生成）
- 「一辺 40mm の立方体の中心に、直径 20mm の貫通穴をあけて」
- 「外径 30mm・内径 20mm・高さ 15mm のパイプを作って」

### 指示の例（STL 編集）
- 「上面の中央に直径 10mm の穴を深さ 5mm であけて」
- 「全体を 1.2 倍に拡大して」

## 技術スタック
- **3D 描画:** [Three.js](https://threejs.org/) r160（CDN + importmap）
- **ブーリアン演算:** [three-csg-ts](https://github.com/samalexander/three-csg-ts) 3.2.0
- **LLM:** Gemini API（REST、ブラウザから直接呼び出し）

依存はすべて CDN から解決するため、**ビルド不要**。`index.html` を静的配信するだけで動きます。

## 動的コード実行の契約
チャット/コード直接入力で実行される JS には、次が引数として渡されます。

| 変数 | 内容 |
| --- | --- |
| `scene` | 表示中の `THREE.Scene` |
| `THREE` | Three.js 名前空間 |
| `CSG` | three-csg-ts の `CSG` クラス（`union` / `subtract` / `intersect`） |
| `targetMesh` | 現在の操作対象メッシュ（無ければ `null`） |
| `setResult(mesh)` | 完成メッシュを 1 つ登録する関数 |
| `mergeMeshes(meshes)` | 複数メッシュを **CSG を使わず**1 つに合成する関数（重なっていない形状専用） |

- 完成メッシュは必ず `setResult(mesh)` で登録します（`scene` への add は不要）。
- CSG 演算の前に、関与する各メッシュで `mesh.updateMatrix()` を呼んでください。
- 穴が複数あるときは、切削体を `mergeMeshes([...])` でまとめて **`subtract` を 1 回**にします。

```js
// 板に穴を2つあける例（CSG は1回だけ）
const plate = new THREE.Mesh(new THREE.BoxGeometry(60, 40, 6));
const holes = [-18, 18].map((x) => {
  const h = new THREE.Mesh(new THREE.CylinderGeometry(3, 3, 10, 12)); // 半径3mm→12分割で十分
  h.rotation.x = Math.PI / 2;
  h.position.set(x, 0, 0);
  return h;
});
const cutter = mergeMeshes(holes);   // ここは CSG を使わないので軽い
plate.updateMatrix();
cutter.updateMatrix();
setResult(CSG.subtract(plate, cutter));
```

## ⚠ セキュリティに関する注意
